## 새 E2E가 확인한 경계 조건
- 로그인 전 보호 경로와 가짜 문서 ID 접근, 비인증 refresh 401, 교차 출처 쓰기 403, 데모 쿠키 상태의 실제 API 403.
- 로그인 건너뛰기 시 실계정 인증 쿠키 미설정, 서로 다른 브라우저 프로필 데이터 분리, 데모 새로고침과 로그아웃 후 재로그인.
- 필수 경험 질문 누락 시 완료 불가, 경험별 사용자 정의 질문/답변 유지, 경험 삭제 취소.
- 채용공고 잘못된 URL 거부 및 한글·HTML 기호 본문 저장/복원.
- 자소서 문항 추가 유효성, 이모지 글자 제한, 문항 순서 이동·삭제·버전 복원, 정보 수정과 지원 카드 표시 동기화.
- 지원 검색/필터, 월간 캘린더 이동, 칸반 Drag & Drop, 다른 단계로 카드 추가 및 새로고침 후 유지.
- 면접 답변 브라우저 저장·삭제·복원, 1분 타이머 시작·정지·초기화.

## 발견한 문제와 조치
1. **P1: 지원 카드 추가 팝업 Esc 키 동작 없음.** Esc로 닫기, 최초 입력칸 포커스, Tab/Shift+Tab 순환 및 닫힌 후 트리거 포커스 복귀 구현.
2. **P1: 지원 카드 상세 팝업 Esc 키 동작 없음.** 동일 키보드 탐색·포커스 복원 구현, 지원 단계 선택 레이블 명시 연결.
3. **P2: 카드 상태 배지 대비 부족.** 채워진 카드의 `text-primary-60` 대비비 약 4.19:1로 WCAG AA 미달. `text-primary-70`로 조정, 수정 후 다이얼로그 6회 axe 위반 0건.
4. 첫 35개 경계 시나리오의 **31 PASS / 4 FAIL** 중 3건은 테스트 선택자/비동기 대기 문제여서 테스트 코드 수정. 나머지는 카드 생성 팝업 Esc 버그. 삭제 확정·영속 삭제 2건을 추가하여 최종 수정본 **37 PASS / 0 FAIL**.

## 재실행 방법
```powershell
cd "C:\Users\1234\Desktop\졸프_FE"
npm ci
npm run build
npm run start -- -p 3006
# 별도 터미널
$env:QA_E2E_BASE="http://localhost:3006"
npm run qa:e2e
```
- 기본값은 Vercel 주소, `QA_E2E_BASE`를 설정하면 프로덕션 로컬 서버나 승인된 Preview 주소에서 실행할 수 있다.
- Windows Chrome 기본 실행 경로를 사용한다. 필요 시 `CHROME_PATH` 환경변수로 변경한다.
- 재현 스크립트는 `qa/e2e/*.cjs` 6개이며, 독립 브라우저 프로필에서 **데모 데이터만 생성**한다. 실계정이나 인증정보를 넣지 않는다.
- 스크립트 출력 JSON/캡처는 `qa/e2e`에서 Git 제외. 아래 결과 파일은 심화 QA 당시 스냅샷이다.
