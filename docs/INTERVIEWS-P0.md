## 사용자 흐름
1. 로그인 또는 개발용 로그인 패스 → 좌측 LNB `면접` → `/interviews`.
2. 기존 자소서 목록(실제 `GET /api/cover-letters`)에서 회사 선택. 기업/직무 검색 및 지원 단계 필터.
3. `/interviews/{coverLetterId}`에 진입 → 실제 자소서 상세(문항·답변) 및 지원 상세(면접일)를 읽는다.
4. 고정된 기본·직무 질문 + 문항별 자소서 기반 **템플릿 질문**으로 답변 연습. 회사·직무 텍스트 치환뿐이며 **AI 생성이 아니다**.
5. 질문별 1/2/3분 타이머, 답변 작성(6000자), 완료 체크, 자소서 원문 참고, 진행률 표시.
6. **저장 버튼을 누르는 경우에만** 이 브라우저의 localStorage에 답변과 진행률을 보존한다. 저장된 기록 다시 로딩 / 답변 TXT 내보내기 / 기록 완전 초기화 지원.
7. 지원 상세에서 면접으로, 자소서 편집기에서도 면접으로 이동 가능.

## 보안 및 사용자 데이터 범위
- 기존 Next 프록시가 JWT 쿠키를 보유해 실제 자소서 목록/상세·지원 상세 조회만 백엔드에 요청한다.
- 사용자가 작성한 연습 답변은 **EC2에 보내지 않는다**. 브라우저 localStorage에 저장 시 평문으로 남아있으므로 공용 PC·민감한 정보에 주의한다. 화면에 경고 표시.
- 저장 키는 `pofit_interview_practice_v1_<scope>_<coverId>`, scope는 개발용 미리보기(`preview`) 또는 프로필 API에서 확인한 실제 `memberId`를 사용한다. 로그아웃 후 다른 계정으로 로그인해도 자신의 키만 읽도록 논리적으로 분리했다.
- 프로필 API로 소유자를 확인하지 못하면 로컬 저장 기능을 비활성화하고 TXT 내보내기만 허용한다.
- 인증 없이 접근 시 로그인으로 전환하고 개발 로컬에서만 `pofit_dev_preview` 쿠키가 대체 가능하다. 개발 미리보기에서도 연습 답변이 EC2로 전송되지 않는다.
- 로컬 브라우저에 저장하는 면접 답변은 암호화되지 않으며 브라우저 데이터를 지우면 사라진다. 다른 기기와 동기화되지 않는다.
- 실서비스 계정별 안전한 영구 보관·면접 세션 데이터는 **백엔드 구현 전에는 제공하지 않는다.**

## 정적 확인 및 후속 QA
- ESLint, TypeScript, Next.js 프로덕션 빌드가 완료되면 결과를 변경 로그에 기록한다.
- 이번에는 기존 EC2 데이터를 수정하지 않았으며 실제 QA 계정으로 면접/자소서 종합 E2E를 실행하지 않았다.
- QA 예정: 로그인 상태·만료, 자소서 로딩/404, 기록 저장→재진입, 계정 교체→기록 분리, 미저장 이동, 내보내기 한글 텍스트, 타이머, 6000자 제한, 빈 자소서, 날짜 오류, 1440/1023/720/360 반응형, 키보드/스크린리더.
- 후속 작업: **백엔드 면접 세션 및 AI 생성·피드백 API 도입**, 디자인팀 면접 프레임 확보 후 화면 정합성 대조, 실제 로그인 계정 E2E.
